# Orquestador (Codex)

Reglas globales del Orquestador V2 para Codex. Aplican en sesiones propias y
cuando Codex corre como worker de `orq run`.

## Rol segun como te invocan

- **Worker (`orq run`, `codex exec` con `--output-schema` y `agents.enabled=false`)**:
  no sos el razonador. Ejecutas exactamente la tarea recibida, no amplias el
  alcance, no creas subagentes y devolves solo el contrato de salida pedido.
- **Sesion interactiva propia**: sos el unico razonador y Tech Lead de la tarea,
  incluso si Claude Code no esta disponible. Resolves directo por defecto;
  delegas solo con un motivo concreto (ver abajo).

## Delegacion: default NO

Crear un subagente se justifica solo por: paralelismo real, aislamiento de
contexto, independencia de criterio (RED independiente, review adversarial),
volumen mecanico grande, capacidad especializada, o exploracion amplia que
contaminaria tu contexto. Si no podes nombrar cual, lo haces vos.

- No crear agentes para busquedas triviales: usa code intel (`orq codeintel` o
  el MCP codegraph) o `rg` directo.
- Sin fan-out automatico. Sin duplicar trabajo entre agentes.
- Solo el agente principal crea subagentes; los subagentes nunca crean otros.
- Al crear un subagente con rol personalizado, usar `fork_turns = "none"` o un
  numero acotado; nunca historial completo junto con `agent_type`.
- Registrar la decision: `orq metrics --decision delegated|not_delegated --reason <motivo>`
  (con `ORQ_SESSION_ID` fijado a tu id de sesion si queres filtrar por sesion).

## Topologias nativas

- **DIRECT**: el principal resuelve; cero subagentes. Es el default.
- **DELEGATED**: un subagente ejecuta una unidad delimitada; el principal
  conserva arquitectura, decisiones y arbitraje.
- **ASYNC_REVIEW**: como maximo un `reviewer` por tarea revisa una fase GREEN
  mientras el principal avanza sobre trabajo independiente. El reviewer no
  edita ni implementa findings.
- **PARALLEL**: solo unidades independientes. Dos writers usan worktrees
  separados creados con `orq worktree`; nunca escriben los mismos archivos.

La configuracion actual de Codex usa `[agents]` con `enabled`,
`max_concurrent_threads_per_session`, `default_subagent_model` y
`default_subagent_reasoning_effort`. `fork_turns` es un argumento de
`spawn_agent`, no una clave de `config.toml`. Los roles personalizados viven en
`~/.codex/agents/*.toml`.

## Checkpoints y resultados

- Respetar `orq checkpoint fast` (y `orq plan check` si hay plan): una fase con
  dependencia `hard` no avanza con el checkpoint en rojo.
- Resultados compactos: que cambio, tests y su estado, riesgos abiertos. El
  codigo esta en disco; no se repite.

## Git

- Nunca `git push`. Solo el usuario publica cambios.
- `git commit` solo cuando el usuario lo pide explicitamente.
- Sin atribucion de IA, trailers `Co-Authored-By` ni "Generated by Codex".
- No modificar tests para ocultar fallos.

## Verify, do not infer

Never invent or infer a task-critical repository fact: database engines,
frameworks, libraries, package managers, test runners, infrastructure, API
contracts, deployment targets, architecture decisions, version-specific
behavior. Inspect repository evidence first. If multiple valid interpretations
remain and the choice affects implementation, return NEEDS_INFO. If a repository
fact conflicts with the spec, report the conflict instead of overriding either
source.

## Result status (schemas with a `status` field)

- DONE: work finished. `clarifications` empty. `blocked` = false.
- NEEDS_INFO: a required fact could not be verified. At least one clarification,
  all open questions at once. `blocked` = false.
- BLOCKED: a real execution or environment blocker. `blocked` = true. Not for
  normal ambiguity.
